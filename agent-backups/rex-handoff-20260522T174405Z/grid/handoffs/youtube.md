# YouTube / Short-Form Handoffs

## 2026-05-16 — 5 short-form concepts: simple web apps under 1 minute

Tone target: practical, exciting, beginner-accessible, build-in-public. These are “demo a tiny working version fast” concepts, not claims that the app is polished or production-ready.

---

### 1) Hook/title: **Tiny Poll App**

**App idea demoable in ~60 seconds:** A one-question poll page where viewers can vote between two options and see live-updating counts stored locally or in a simple backend.

**45–60 sec spoken script:**
“Here’s a tiny web app you can build in under a minute: a poll that actually feels interactive. I’m starting with one question — ‘Which feature should I build next?’ — and two buttons. Now I’ll add a little state for the vote counts, wire each button to increase its number, and render the results underneath. That’s already a working demo. To make it feel more real, I’ll add a progress bar so you can instantly see which option is winning. Is this a full production polling platform? Definitely not. But it is the perfect beginner app because it teaches buttons, state, events, and UI feedback in one tiny project. If you’re learning web apps, build this first, then upgrade it with saved votes or shareable links.”

**Shot-by-shot / screen-action beats:**
- 0–3s: Face cam or screen title: “Build a poll app in 60 seconds.”
- 3–10s: Create simple page with question and two option buttons.
- 10–22s: Add vote count state for Option A / Option B.
- 22–34s: Click buttons and show numbers increasing.
- 34–46s: Add percentage/progress bars.
- 46–55s: Quick demo: vote twice, show the result changing.
- 55–60s: Show “next upgrade: save votes + share link.”

**Caption keywords / on-screen text:**
- “simple web app”
- “beginner project”
- “state + events”
- “interactive UI”
- “not production-ready yet — tiny MVP”

**CTA:**
“Comment ‘POLL’ and I’ll share the starter code / next upgrade.”

### 2) Hook/title: **One-Minute Habit Tracker**

**App idea demoable in ~60 seconds:** A 7-day habit tracker with clickable checkboxes, streak count, and local save.

**45–60 sec spoken script:**
“Let’s build a tiny habit tracker in under a minute. I only need three pieces: the habit name, seven days, and a streak count. First I’ll lay out the week as seven little squares. Then I’ll make each square clickable, so every tap toggles complete or incomplete. Now we calculate the streak by counting checked days and display it at the top. The cool part is how fast this starts feeling like a real app — one click and the interface responds. If I want to push it one step further, I can save the checked days in local storage so refreshing the page doesn’t wipe my progress. This is a great beginner project because you learn arrays, clicks, conditional styling, and saving simple data without building something huge.”

**Shot-by-shot / screen-action beats:**
- 0–4s: Show blank page and text: “Habit tracker MVP.”
- 4–12s: Add habit title: “Drink water” and seven day boxes.
- 12–24s: Add click/toggle behavior.
- 24–34s: Style completed boxes green/checkmarked.
- 34–45s: Add streak counter at the top.
- 45–54s: Refresh page after adding local storage.
- 54–60s: Show finished tiny app on mobile width.

**Caption keywords / on-screen text:**
- “habit tracker”
- “local storage”
- “click to complete”
- “beginner JavaScript app”
- “tiny MVP, real interaction”

**CTA:**
“Want part two? I’ll add calendar history and reminders.”

### 4) Hook/title: **Instant Tip Calculator**

**App idea demoable in ~60 seconds:** A bill splitter that calculates tip, total, and per-person cost from three inputs.

**45–60 sec spoken script:**
“Let’s make a useful web app in under a minute: a tip calculator and bill splitter. I’ll start with three inputs: bill amount, tip percentage, and number of people. Under that, I’ll show three outputs: tip amount, total, and cost per person. Now I’ll connect the math. When the bill changes, the app recalculates instantly. When the tip changes, same thing. When the number of people changes, we divide the total and update the per-person amount. This is a great beginner app because it’s small, practical, and teaches input handling, validation, and live calculations. It’s not a banking-grade finance tool — it’s a clean demo you can build on. Add better styling, currency formatting, and mobile layout, and suddenly it feels like something you’d actually use.”

**Shot-by-shot / screen-action beats:**
- 0–4s: Show restaurant bill visual / title: “Tip calculator in 60 sec.”
- 4–14s: Build three inputs: bill, tip %, people.
- 14–27s: Add output labels for tip, total, per person.
- 27–40s: Wire calculation logic and test changing values.
- 40–50s: Add currency formatting and guard against 0 people.
- 50–60s: Mobile preview: enter bill, show instant result.

**Caption keywords / on-screen text:**
- “tip calculator”
- “live calculations”
- “input handling”
- “beginner web app”
- “practical mini project”

**CTA:**
“Comment ‘CALC’ if you want the next version with presets and dark mode.”

### 5) Hook/title: **AI Prompt Saver**

**App idea demoable in ~60 seconds:** A tiny prompt library where you add, tag, search, and copy prompts locally.

**45–60 sec spoken script:**
“Here’s a tiny app idea I’d actually use: an AI prompt saver. In under a minute, we can make the first version. I’ll add a text box for the prompt, a tag field like ‘writing’ or ‘coding,’ and a save button. When I click save, the prompt appears in a list below. Now I’ll add a search box, so typing ‘coding’ filters the list instantly. Finally, every saved prompt gets a copy button, because the whole point is to reuse it quickly. This is beginner-friendly, but it feels modern because it solves a real workflow problem. To be clear, this is a local MVP, not a polished team prompt manager. But it’s perfect for learning forms, lists, filtering, local storage, and building tools for yourself.”

**Shot-by-shot / screen-action beats:**
- 0–4s: Title: “Build your own prompt library.”

- 13–24s: Save first prompt and render it as a card.
- 24–35s: Add multiple prompts with different tags.
- 35–45s: Add search/filter input and demonstrate filtering.
- 45–54s: Add copy button and show copied state.
- 54–60s: Show local MVP and list upgrade ideas.
