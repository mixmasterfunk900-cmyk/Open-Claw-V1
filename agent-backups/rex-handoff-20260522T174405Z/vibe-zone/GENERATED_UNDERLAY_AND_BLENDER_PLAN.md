# Generated Underlay + Blender Plan

_Last researched: 2026-05-13 UTC. Planning only: no paid generation, account connection, public upload, or exposed service setup was performed._

## Goal

Create unique visual/render layers that sit **under Masala’s facecam / talking-head crop** for Shorts/Reels/TikToks, making clips feel less like raw livestream reposts while staying cheap, fast, stream-safe, and repeatable.

The underlay should:
- Fill dead space and prevent boring black bars.
- Keep Masala’s face clear and readable.
- Match the clip mood: hype, funny, technical, “big idea”, chaos, calm build mode.
- Avoid copyright issues by using generated/procedural/local assets.
- Produce platform-native 9:16 outputs with safe zones for captions and UI chrome.

## Recommendation

Use a staged approach:

1. **Now: local procedural FFmpeg/Canvas underlays**
   - Fastest, cheapest, deterministic, no credentials.
   - Generate animated gradients, waveforms, grids, code rain, particle dots, blurred source motion, waveform-reactive pulses, and branded “Vibe Zone” loops.
   - Integrate directly into current render presets.

2. **Next: Remotion-style React video templates**
   - Vibe Zone is already React/TypeScript, so Remotion is the most natural programmatic-video path.
   - Use reusable components for animated backgrounds, hook cards, lower thirds, proof cards, and per-platform layout variants.

3. **Later: Blender headless render templates**
   - Great for premium 3D loops: neon desk, hologram Rex, spinning product cards, terminal/code worlds, abstract kinetic machines.
   - Use EEVEE/Workbench for quick previews; Cycles only for high-quality hero loops.
   - Render image sequences then encode with FFmpeg for resilience.

4. **Optional paid/AI video layer: OpenAI/Sora or other video APIs only after approval**
   - Use for occasional hero underlays, not every clip.
   - Prefer image generation + local animation first; full video generation can be costly, slow, and subject to policy/deprecation changes.

## Layout principle: facecam-first

Underlays must never compete with the face.

Recommended composition for 9:16:
- Facecam/talking head: upper/middle safe region, tracked by existing `facecam-smart` crop metadata.
- Captions: Shorts-safe lower third, never over mouth/eyes.
- Underlay: fills background behind face crop and unused vertical space.
- Hook card: first 1–2 seconds, high-contrast top/mid text; face still visible if possible.
- Motion: subtle enough to add energy without reducing caption legibility.

Every generated-underlay render should output review metadata:

```json
{
  "underlay": {
    "kind": "procedural-gradient" | "remotion-template" | "blender-loop" | "ai-video" | "blurred-source",
    "templateId": "string",
    "seed": "string",
    "palette": ["#..."],
    "motionIntensity": 0.0,
    "aiGenerated": false,
    "license": "local-generated" | "open-source" | "paid-api" | "unknown",
    "renderSeconds": 42.3,
    "reviewNotes": "safe, no text collision"
  }
}
```

## Option A — Local FFmpeg procedural visuals

**Best first prototype.**

What to generate:
- Animated gradients with `geq`, `color`, `blend`, `zoompan`, `frei0r` if installed.
- Audio-reactive waveform/spectrum with `showwaves`, `showfreqs`, `showspectrum`, `avectorscope`.
- Blurred/enlarged source video background: scale/crop/boxblur/darken behind clean face crop.
- Procedural shapes from generated SVG/PNG frames.
- CSS/Canvas-rendered frames piped to FFmpeg.
- “Code rain” / terminal typing / grid pulse generated by Node scripts to PNG frames.

Why it fits now:
- No external account/API.
- Works with existing Node + FFmpeg render scripts.
- Cheap enough for many variants per clip.
- Deterministic seeds allow reproducibility.
- Easy to label as local-generated and safe.

Example preset ideas:

1. `underlay-blur-pulse`
   - Uses source video scaled to 9:16, heavy blur, dark overlay, subtle saturation/contrast.
   - Adds a barely visible audio pulse vignette.
   - Lowest-risk default.

2. `underlay-vibe-gradient`
   - Procedural gradient loop with seed from clip ID.
   - Palette based on clip mood: orange/hype, blue/technical, purple/weird, green/build.

3. `underlay-terminal-grid`
   - Animated grid/terminal particles with faint code-like glyphs, no real private code/log content.
   - Good for coding clips.

4. `underlay-audio-reactive`
   - Waveform bars behind facecam, driven by clip audio.
   - Keep opacity low under captions.

Implementation sketch:

```bash
# blurred source underlay, then overlay tracked facecam/captions in existing pipeline
ffmpeg -i input.mp4 -filter_complex "
  [0:v]scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,boxblur=30:2,eq=brightness=-0.18:saturation=1.25[bg];
  [0:v]scale=1080:-2[fg];
  [bg][fg]overlay=x=(W-w)/2:y=120[out]
" -map "[out]" -map 0:a -c:v libx264 -pix_fmt yuv420p output.mp4
```

For procedural frame generation:
- `scripts/generate-underlay-frames.mjs --kind terminal-grid --seed clipId --duration 45 --fps 30 --out media/generated/underlays/...`
- Encode frames with FFmpeg.
- Composite in existing render preset.

Pros:
- Cheap, fast, no blockers.
- Easy to A/B test many variants.
- Fits current Vibe Zone pipeline.

Cons:
- Less “wow” than premium AI/Blender.
- Needs taste/design iteration to avoid looking generic.

## Option B — Remotion / React templates

Remotion lets video be built from React components and rendered to MP4. Since Vibe Zone already uses React/TypeScript, this is a strong medium-term fit.

Use cases:
- Hook cards with animated text.
- Underlay templates with CSS/SVG/canvas animation.
- Social-native end cards.
- Consistent design system for captions, CTAs, proof stats, and facecam masks.
- Template previews inside Vibe Zone UI.

Suggested templates:
- `VibeGradientScene`
- `TerminalGridScene`
- `ClipProofHookScene`
- `AudioWaveScene`
- `LongFormChapterCardScene`
- `RexHologramPlaceholderScene`

Pros:
- React/TS reuse.
- Great for dynamic text/layout.
- Server-side MP4 rendering.
- Easier than Blender for UI-heavy shorts graphics.

Cons/blockers:
- Adds dependency/tooling weight.
- Rendering can be slower than pure FFmpeg for simple backgrounds.
- Need license check for Remotion usage if the product becomes commercial/SaaS. Remotion has commercial licensing considerations; verify before committing to a hosted product.

Sources:
- `https://github.com/remotion-dev/remotion`
- `https://www.remotion.dev/`

## Option C — Blender headless renders

Blender can render from the command line with `-b` / background mode, no graphical display required. Official docs note `-f`/`-a` should come last because arguments execute in order.

Basic commands:

```bash
# Single frame
blender -b scene.blend -o /tmp/render/frame_##### -F PNG -f 1

# Animation
blender -b scene.blend -E BLENDER_EEVEE_NEXT -s 1 -e 240 -o /tmp/render/frame_##### -F PNG -a

# Cycles GPU example when configured/supported
blender -b scene.blend -E CYCLES -s 1 -e 240 -o /tmp/render/frame_##### -F PNG -a -- --cycles-device CUDA
```

Recommended Blender strategy:
- Start with **generated `.blend` templates** via Python, not hand-built fragile scenes.
- Render 5–10 second seamless loops at 1080x1920 or 1080x1080, then loop/trim under clips.
- Prefer EEVEE/Workbench for fast abstract visuals.
- Render image sequences, then encode with FFmpeg (`libx264`, `yuv420p`) rather than direct MP4 for crash resilience.
- Cache loops by template/seed so one render can support many clips.

Good Blender underlay templates:

1. `neon-code-tunnel`
   - Abstract code-like blocks, no real source code.
   - Camera drift through grid.

2. `vibe-desk-hologram`
   - Desk-like scene with glowing panels and Rex placeholder silhouette.
   - Future avatar/hologram direction without needing real likeness.

3. `kinetic-product-cards`
   - Floating cards: “Clip Factory”, “Render Lab”, “Dispatch”.
   - Good for founder/building-in-public clips.

4. `particle-orbit`
   - Abstract orbit particles around a blank center-safe region for facecam.

5. `terminal-city`
   - Low-poly terminal/cityscape with scrolling abstract glyphs.

VPS feasibility:
- CPU-only Blender works for simple EEVEE/Workbench loops but can be slow.
- GPU acceleration needs compatible GPU, drivers, Blender build support, and device config.
- Headless EEVEE support is viable in modern Blender; still test on target server.
- For repeatable production, render/cache loops asynchronously so clip rendering is not blocked.

Pros:
- Distinctive branded look.
- Fully owned/generated visuals.
- Can create premium, reusable loops.

Cons/blockers:
- Blender may not be installed on the VPS.
- GPU availability unknown.
- Slower and more operationally complex than FFmpeg/Remotion.
- Requires design taste and render farm hygiene.

Source:
- `https://docs.blender.org/manual/en/latest/advanced/command_line/render.html`

## Option D — OpenAI / ChatGPT-generated video and images

Current useful stance:
- Use OpenAI image generation for still underlay assets, thumbnails, texture plates, and mood boards when an image-generation provider/API is configured and approved.
- Treat OpenAI/Sora-style video generation as optional and volatile. Official search results indicate OpenAI’s Sora Videos API/models have deprecation timelines in 2026; verify live docs before investing.
- Full AI video generation is best for occasional hero loops, not bulk clip rendering.

Potential workflows:

1. **Image → local motion**
   - Generate a 9:16 abstract background still.
   - Animate locally with FFmpeg zoom/pan, parallax, displacement, particles.
   - Cheapest AI-assisted path.

2. **Prompt → short seamless video loop**
   - Generate 5–10 second loop from a prompt.
   - Cache and reuse across related clips.
   - Requires labeling if materially AI-generated.

3. **Storyboard → Blender/Remotion recreation**
   - Use ChatGPT/image gen for concept art.
   - Rebuild the final loop locally in Blender or Remotion for control/licensing/repeatability.

Safety rules:
- No use of Masala’s likeness/face in AI generation without explicit approval and reference-image consent.
- No fake audience/chat/screenshots.
- No misleading “real footage” underlays.
- Mark `aiGeneratedVisuals: true` and surface the label in Dispatch for TikTok/YouTube metadata decisions.
- Do not include private code, DMs, tokens, emails, or real customer data in generated prompts.

Sources:
- `https://developers.openai.com/api/docs/guides/video-generation` (verify live status before use)
- OpenClaw `image_generate` provider list when/if Masala asks for a configured generation test.

## Option E — Open-source / free asset/template sources

Use sources carefully. Even “free” assets can have attribution or commercial restrictions.

Good categories:
- Generated SVG/CSS patterns created locally.
- Public-domain textures/noise where license is clear.
- Open-source shader snippets only if license allows project use.
- Blender procedural geometry/materials made in-house.
- Remotion examples/templates after checking license.

Avoid:
- Downloading random TikTok backgrounds.
- Ripping game/movie/anime footage.
- Using copyrighted music/loops under clips.
- Including readable private code or real logs as “coding aesthetic”.

## First safe prototype

Build `underlay-blur-pulse` and `underlay-terminal-grid` as local-only render presets.

### Acceptance criteria

For one existing high-potential clip:
- Render 2 variants:
  1. `facecam-smart + underlay-blur-pulse + punchy captions`
  2. `facecam-smart + underlay-terminal-grid + punchy captions`
- Produce proof frames at 0.5s, 2s, middle, and end.
- Store underlay metadata in the render record/export bundle.
- Review for:
  - Face visible.
  - Captions readable.
  - No private text visible.
  - Background motion not nauseating.
  - Looks better than black/flat fill.
- Add a UI label: “Generated local underlay — no external AI/API used”.

### Implementation tasks

1. Add an `underlayPreset` option to render requests:
   - `none`
   - `blur-pulse`
   - `terminal-grid`
   - `vibe-gradient`
2. Add a deterministic seed: `clipId + preset + renderDate`.
3. Add a small Node frame generator for `terminal-grid` / `vibe-gradient` using SVG or Canvas.
4. Add FFmpeg composition helpers:
   - Generate/loop background.
   - Overlay facecam-smart crop.
   - Overlay captions/hook card last.
5. Write render metadata next to output MP4.
6. Add proof-frame generation/review card.
7. Add `aiGeneratedVisuals` boolean and `underlay.kind` display in Dispatch.
